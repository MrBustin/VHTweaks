Mixins Reference - VHTweaks

What A Mixin Is

A mixin is a runtime patch class. In a Minecraft mod, it lets your code change classes you do not own, such as Minecraft, Forge, or The Vault classes.

Instead of editing another mod's source code directly, you write a class that says: when this target class loads, inject or replace specific behavior.

Where This Repo Registers Mixins

The mixin list lives in:

src/main/resources/woldsvaults.mixins.json

"package": "xyz.iwolfking.woldsvaults.mixin",
"mixins": [
  "MixinPlayerInventory",
  "MixinDynamicModelRegistries",
  ...
]

The package is the base folder. Each entry in mixins points to a mixin class under that package.

Basic Shape

@Mixin(value = SomeTargetClass.class)
public class MyMixin {
    // patch methods go here
}

@Mixin chooses the class being patched. The annotations inside the class choose what kind of patch happens.

Example: Injecting Before Inventory Add

src/main/java/xyz/iwolfking/woldsvaults/mixin/MixinPlayerInventory.java

@Mixin(value = Inventory.class, priority = 1500)
public class MixinPlayerInventory {
    @Inject(method = "add(Lnet/minecraft/world/item/ItemStack;)Z",
            at = @At("HEAD"),
            cancellable = true)
    private void handleInterceptingItemAddition(ItemStack pStack,
            CallbackInfoReturnable<Boolean> cir) {
        if (ItemScavengerPouch.interceptPlayerInventoryItemAddition(
                (Inventory)(Object)this, pStack)) {
            cir.setReturnValue(true);
        }
    }
}

This targets Minecraft's Inventory class. It runs at the start of Inventory.add(ItemStack).

If the scavenger pouch handles the item, cir.setReturnValue(true) immediately returns true and prevents the original inventory logic from continuing.

boolean add(ItemStack stack) {
    if (ItemScavengerPouch.interceptPlayerInventoryItemAddition(this, stack)) {
        return true;
    }

    // normal Minecraft inventory code
}

Example: Injecting After A Method Returns

src/main/java/xyz/iwolfking/woldsvaults/mixin/MixinDynamicModelRegistries.java

@Inject(method = "getUniqueRegistries",
        at = @At("RETURN"),
        cancellable = true)
public void addArmorModelRegistry(CallbackInfoReturnable<Set<DynamicModelRegistry<?>>> cir) {
    Set<DynamicModelRegistry<?>> registries = new HashSet<>(cir.getReturnValue());
    registries.add(ModDynamicModels.Armor.MODEL_REGISTRY);
    cir.setReturnValue(Collections.unmodifiableSet(registries));
}

This preserves the original return value, adds the armor model registry, then replaces the returned set.

Example: Redirecting One Method Call

src/main/java/xyz/iwolfking/woldsvaults/mixin/the_vault/custom/MixinPylonBlock.java

@Redirect(method = "playerDestroy",
        at = @At(value = "INVOKE",
        target = "Liskallia/vault/config/TemporalShardConfig;getDropChance()F"))
private float modifyChance(TemporalShardConfig instance, Player player, Level level) {
    return instance.getDropChance() + getPylonPilfererBonus(player);
}

This targets PylonBlock.playerDestroy. When the original method calls TemporalShardConfig.getDropChance(), this mixin replaces that call with one that adds the player's Pylon Pilferer bonus.

Example: Modifying A Constructor Argument

src/main/java/xyz/iwolfking/woldsvaults/mixin/the_vault/custom/MixinVaultXPFoodItem.java

@ModifyVariable(
        method = "<init>(Lnet/minecraft/resources/ResourceLocation;Lnet/minecraft/world/item/Item$Properties;I)V",
        at = @At("HEAD"),
        index = 3,
        argsOnly = true)
private static int clampConstructorArg(int originalLevelLimit) {
    if (originalLevelLimit == -1 || originalLevelLimit > DEFAULT_LEVEL_CAP) {
        return DEFAULT_LEVEL_CAP;
    }
    return originalLevelLimit;
}

This changes the levelLimit constructor argument before VaultXPFoodItem uses it. In this repo, XP food is capped at level 100.

Accessors And Invokers

Accessor

src/main/java/xyz/iwolfking/woldsvaults/mixin/LivingEntityAccessor.java

@Mixin(value = LivingEntity.class)
public interface LivingEntityAccessor {
    @Accessor("lastHurt")
    void setLastHurt(float lastHurt);
}

An accessor exposes a field from the target class. Here, code can set Minecraft's internal LivingEntity.lastHurt field.

Invoker

src/main/java/xyz/iwolfking/woldsvaults/mixin/GameRulesBooleanValueAccessor.java

@Mixin(GameRules.BooleanValue.class)
public interface GameRulesBooleanValueAccessor {
    @Invoker("create")
    static GameRules.Type<GameRules.BooleanValue> create(boolean defaultValue) {
        throw new AssertionError();
    }
}

An invoker exposes a method from the target class. The body throws because Mixin replaces it at runtime.

Example: Wrapping An Operation

src/main/java/xyz/iwolfking/woldsvaults/mixin/MixinItemStack.java

@WrapOperation(
        method = "hurt",
        at = @At(value = "INVOKE",
        target = "Lnet/minecraft/world/item/ItemStack;getItem()Lnet/minecraft/world/item/Item;"))
public Item gearDurabilityPrestigeForWoldItems(ItemStack instance, Operation<Item> original) {
    Item item = original.call(instance);

    if (item instanceof VaultMageStaffItem
            || item instanceof VaultTridentItem
            || item instanceof VaultPlushieItem
            || item instanceof VaultLootSackItem
            || item instanceof VaultRangItem) {
        return ModItems.FOCUS;
    }

    return item;
}

@WrapOperation lets the mixin call the original operation, inspect the result, and optionally return something else. Here, custom Wold gear items pretend to be ModItems.FOCUS for part of the durability logic.

Example: Overwriting Entire Methods

src/main/java/xyz/iwolfking/woldsvaults/mixin/the_vault/custom/MixinWildSpawnerTileEntity.java

@Overwrite
private static void spawnEntity(...) {
    ...
}

@Overwrite
private void initSpawnerGroup() {
    ...
}

@Overwrite replaces the whole target method. This repo uses it to change Vault Hunters wild spawner behavior for haunted/spooky vaults and buffed wraith spawning.

Rule of thumb: use @Overwrite sparingly. It is powerful, but if the original mod updates that method later, your overwrite does not automatically inherit those fixes.

Other Common Annotations

  • @Shadow: declares a field or method that already exists in the target class so your mixin can reference it.
  • @Unique: marks helper fields or methods owned by the mixin so they do not collide with target members.
  • @At("HEAD"): inject at the beginning of a method.
  • @At("RETURN"): inject after the method has produced a return value.
  • CallbackInfo: callback object for void methods.
  • CallbackInfoReturnable<T>: callback object for methods that return a value.

How To Think About Mixins

Pick the smallest patch that changes the behavior you need:

  • Use @Inject when you can add behavior before or after a method.
  • Use @Redirect or @WrapOperation when one specific call needs to change.
  • Use @ModifyVariable when an argument or local variable needs adjustment.
  • Use @Accessor or @Invoker when you only need access to hidden data or methods.
  • Use @Overwrite only when smaller patch points cannot express the change clearly.

The short version: a mixin is a runtime patch class. In this repo, mixins let VHTweaks alter Minecraft and Vault Hunters behavior without directly editing their source code.
